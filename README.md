# Лабораторна робота 5

Алгоритми ковзного вікна для обробки часових рядів. Виконано обидві групи вимог II рівня: прогнозування, оптимізацію параметрів, порівняння зі статистичним навчанням і дослідження довгої екстраполяції.

## Запуск

Потрібні Python 3.12+ та uv. Залежності зафіксовані в `uv.lock`.

```powershell
uv sync --frozen
uv run --frozen python -B -X utf8 main.py
```

У PyCharm виберіть `.venv/Scripts/python.exe` та запустіть `main.py`. Після встановлення залежностей обчислення не потребують мережі. Вхідні дані й стандартна папка результатів визначаються від розташування скрипта.

Повний запуск використовує seed 42 та по 100 незалежних реалізацій трьох синтетичних сценаріїв. Для швидкої перевірки:

```powershell
uv run --frozen python -B -X utf8 main.py --simulations 30 --output results_quick
```

Доступні також `--data`, `--output`, `--seed`. Папки результатів створюються автоматично; новий запуск у тій самій папці перезаписує однойменні результати.

## Що реалізовано

- Причинне ковзне згладжування; ACF/PACF, ADF/KPSS.
- Рекурсивний SMA, ARMA, ARIMA, Ridge на лагах та поліноміальні МНК-моделі. Наївний і сезонний наївний прогнози — базові моделі.
- 34 конфігурації, хронологічний вибір параметрів, журнал незбіжних оцінювань.
- Фіксований 12-місячний тест і rolling-origin перевірка без зміни гіперпараметрів за результатами тесту.
- Порівняння налаштованих і наперед заданих моделей, MAE/RMSE/bias/sMAPE, час розрахунків.
- Умовні 95% прогнозні інтервали ARMA/ARIMA, покриття та interval score.
- Екстраполяція на 35, 69, 104 і 138 місяців для кожної відібраної моделі.
- 300 синтетичних продовжень із відомим майбутнім, оцінка всіх чотирьох горизонтів та парне порівняння SMA18 із SMA3.
- Дослідження DataSet №8 з умовною екстраполяцією за індексом наступної наявної дати.
- 10 рисунків, таблиці CSV та підсумок JSON.

## Дані та протокол

Steam: 69 повних місяців від грудня 2020 до серпня 2026; неповний вересень зі знімка 21.09.2026 виключено. Походження збережене в metadata JSON. Реальні сплески не видаляються. Моделі працюють у `log(1 + кількість)`; вихідний точковий прогноз — невід'ємне обернене перетворення прогнозу в log-шкалі, не скориговане на логнормальне середнє.

Перші 36 місяців — початкова історія. Валідаційні origins: 36, 39, …, 54; горизонти 1, 3, 6 лише в межах перших 57 місяців. Для h=1 і h=3 доступні сім помилок, для h=6 — шість. Критерій — середнє трьох RMSE у log-шкалі. Конфігурацію з будь-якою невдачею оптимізатора на валідації виключено повністю.

Останні 12 місяців не беруть участі у виборі параметрів. У `fixed_12` модель навчається на перших 57 місяцях та прогнозує всі наступні 12 без доступу до їхніх фактичних значень. У `rolling_1` коефіцієнти переоцінюються на історії, доступній перед кожним місяцем, а гіперпараметри залишаються зафіксованими. Для інших h кількість тестових помилок зменшується до однієї; перекриття прогнозів не робить їх незалежними.

Дискретна домовленість для екстраполяції — `ceil(ratio * 69)` місячних спостережень. Між першою та останньою датою є 68 проміжків; цей альтернативний спосіб визначення довжини не використовується. Відсутнє реальне майбутнє не підмінюється навчальними даними: довгі горизонти оцінюються на синтетичних продовженнях.

Гіперпараметри зі Steam зафіксовані й переносяться в синтетичні сценарії. Коефіцієнти кожної моделі оцінюються заново на перших 69 точках кожної реалізації. Сценарії: стаціонарний ARMA-процес; той самий процес із плавним трендом; невідома майбутня зміна рівня. Це не доказ універсальної оптимальності параметрів. Таблиці містять число успішних оцінювань, а невдачі збережені окремо. Інтервали середнього RMSE — похибка Монте-Карло, не прогнозні інтервали спостережень. Парне порівняння SMA використовує однакові реалізації.

DataSet №8: 15 операцій за дев'ять нерегулярних дат січня 2015. Збережено 10 аналітичних полів без імен і адрес клієнтів. Пропущені дати невідомі, нулі не додаються. Валідація SMA — дві точки, фіксований тест — три. Горизонти 5, 9, 14, 18 означають наступні **наявні дати**, календарний час яких невідомий. `sales_conditional_extrapolation.csv` містить повні 18 кроків, із яких отримуються коротші префікси. Оцінки ілюстративні; ARMA/ARIMA не підганяються до дев'яти нерегулярних точок.

SMA означає просте ковзне середнє. MA(q) в ARMA — модель через минулі випадкові збурення; це інший метод. ARMA(p,q) реалізовано через ARIMA(p,0,q). ARIMA із d=1 використовується без drift, ARMA — зі сталою. Ridge стандартизує лагові ознаки лише за навчальною історією й рекурсивно використовує власні прогнози.

## Результати та структура

`main.py` — запуск; `data_loader.py` — завантаження; `models.py` — моделі; `evaluation.py` — валідація й метрики; `synthetic_data.py` — експерименти; `analysis.py` — послідовність дослідження; `visualization.py` — рисунки.

Ключові результати: `analysis_summary.json`, `validation_ranking.csv`, `test_comparison.csv`, `optimization_effect.csv`, `test_interval_scores.csv`, `extrapolation_*.csv`, `synthetic_summary.csv`, `synthetic_optimization_pairs.csv`, `sales_test.csv`, `figures/`.

Переможець валідації — ARIMA(1,1,1). На фінальному році сезонний наївний прогноз кращий за складніші моделі. Налаштування SMA та ARMA покращує їхні результати проти заданих базових конфігурацій, але довга екстраполяція залишається умовною щодо моделі. 100% покриття 12 тестових значень не доводить каліброваність інтервалів: важливі також їхня ширина та результати синтетичних сценаріїв.
